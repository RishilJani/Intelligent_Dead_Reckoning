## 2. Unused / noisy columns — what was removed

Train/val/test `.npz` files **never stored** the unused CSV columns. Only the 10 IMU feature channels + speed/yaw labels are kept. This audit rewrote the three NPZs to drop any accidental extras and add `feature_names`.

**Not in NPZ (intentionally unused / noisy for this model):**
- phone GPS lat/lon/speed/accuracy/satellites
- magnetometer
- orientation yaw/pitch/roll
- gravity axes (used only for mount alignment at load time)
- steering, wheel speeds, gear, brake, engine, etc.

**Lat/lon in NPZ?** `False` — Latitude/longitude are used only in load_session for GPS-teleport filtering and later trajectory evaluation from raw V-CSVs; they are NOT model inputs and are intentionally absent from train/val/test.npz.

## 3. Parameters in train / val / test NPZ

### Feature channels (`X` last dim = 10)

0. `accel_x`
1. `accel_y`
2. `accel_z`
3. `gyro_x`
4. `gyro_y`
5. `gyro_z`
6. `accel_mag`
7. `linear_accel_mag`
8. `gyro_mag`
9. `jerk`

### Labels
- `y` / `y_raw`: Indicated Vehicle Speed (km/h) — `y` is z-scored
- `y_yaw` / `y_yaw_raw`: CAN Yaw Rate (deg/s) — `y_yaw` is z-scored
- Stats keys: `feat_mean`, `feat_std`, `label_mean`, `label_std`, `yaw_mean`, `yaw_std`
- `feature_names`: string array of the 10 channel names

### NPZ structure (same keys for train, val, test)

```
test.npz  (and train.npz / val.npz)
├── X            float32  (N, 20, 10)  # 2s @10Hz windows, z-scored features
├── y            float32  (N,)         # normalized speed
├── y_raw        float32  (N,)         # speed km/h
├── y_yaw        float32  (N,)         # normalized yaw
├── y_yaw_raw    float32  (N,)         # yaw deg/s
├── feat_mean    (10,)                 # from TRAIN only
├── feat_std     (10,)
├── label_mean   ()
├── label_std    ()
├── yaw_mean     ()
├── yaw_std      ()
└── feature_names (10,) object/str
```

### What is fed to the model

- **Input tensor:** `(batch, 20, 10)` = last 2 seconds of phone IMU (accel xyz, gyro xyz, accel_mag, linear_accel_mag, gyro_mag, jerk), normalized with train `feat_mean`/`feat_std`.
- **Outputs (`MultiTaskRegressor`):** (1) **speed** in normalized space → denorm to km/h; (2) **yaw rate** in **deg/s** (gyro residual head, already physical).
- The model does **not** predict latitude/longitude directly. Position is reconstructed later by integrating predicted speed + heading.

1. **Vehicle speed (km/h)** — trained against VBOX/CAN *Indicated Vehicle Speed*
2. **Yaw rate (deg/s)** — trained against vehicle CAN *Yaw Rate*

Checkpoint used: `best_multitask_model.pt`

- Test moving/stopped AUC=0.748, accuracy=0.876; within-10 km/h accuracy=0.220.
